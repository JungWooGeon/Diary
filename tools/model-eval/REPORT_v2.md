# 온이 프롬프트 v2 평가 (2026-11-21)

## 결론

### E2B
- 답장 점수가 올랐다.
  - 기존 일기 30편: 4.40 → **4.66**
  - 새로 쓴 어려운 일기 20편: 4.02 → **4.61**
- 반어 일기 14편(평가셋 8 + 따로 떼어 둔 6)은 모두 비꼬는 말로 감지했다.
  - 답장이 절반쯤 곧이곧대로인 경우가 1편(x01) 남았다.

### E4B
- 기존 30편: 4.70 → **4.72**
- 어려운 20편: 4.30 → **4.72**
- 반어 14편을 모두 감지했다.
- 감정 JSON도 좋아졌다.
  - 1순위 감정 일치: 38/50 → 44/50
  - 반어 일기를 부정 감정으로 분류: 8/8

### 두 모델 공통
- 존댓말은 0건이다.
- 훈계형 끝맺음은 원본 출력 기준 50편 중 E2B 2건, E4B 1건이다.
  - 모두 후처리 필터가 잡는다.
  - 걸리면 다시 생성하고, 또 걸리면 라이브러리 답장으로 바꾼다. 그래서 사용자에게 보이는 건 0건이다.

### 대가
- 진심으로 칭찬한 일기 6편 중 일부를 반어로 오탐했다. E2B는 3편, E4B는 2편이다.
- 그중 답장까지 틀어진 건 h11 1편(E4B)과 h08·h11 2편(E2B)이다.
- 앱에서는 사용자가 밝음·평온·설렘 쪽 기분을 직접 고르면 반어 감지를 건너뛴다.

## 바뀐 것
앱과 평가는 `shared/ai/llm/prompts.json` 하나를 같이 쓴다. `prompts.py`의 `messages_v2`가 이 파일을 읽는다.

### 답장 (`reply`)
- **새 규칙**
  - "누가 무엇을 했는지 그대로 쓰고, 예전 일을 오늘 일처럼 섞지 마"
  - 반어 단서: 나쁜 일 + 최고·감동·친절·^^
  - 섞인 감정은 둘 다 짚기
  - 짧은 일기나 이모지만 있는 일기에는 2문장, 사연은 지어내지 않기
  - "충고·훈계는 문장 어디에도 쓰지 마. 하고 싶은 말은 '~했겠다, ~구나, 나 여기 있을게'로 바꿔"
- **예시 5개**
  - 조언형으로 끝나던 마감 예시는 뺐다.
  - 반어 예시를 넣었다. 액정이 깨진 '완벽한 하루'이고, 메모가 붙은 형태다.
  - 서운함·주어 예시를 넣었다. 다은이가 내 비밀을 말했고, 나는 지켰다.
  - 한 줄 일기 예시를 넣었다. "배고파서 잠이 안 옴"
- **샘플링과 메모**
  - temperature 0.5
  - Gemma 4 생각 모드는 끈다.
  - 사용자가 고른 기분은 `hints.mood` 메모로 붙인다.

### 반어 감지 (`sarcasm`) — 가장 효과가 컸던 변경
- 규칙만으로는 안 됐다.
  - v2 프롬프트를 써도 E2B는 반어 8편 중 5편을 곧이곧대로 읽었다.
  - 감정 JSON에 sarcasm 칸을 넣는 방식도 3/8에 그쳤다.
- **방식**: 답장 전에 짧은 읽기 호출을 한 번 한다.
  - 출력 형식: `{bad[], praise[], sarcasm}`
  - JSON 스키마로 출력을 강제한다. 약 40토큰이다.
- true면 일기 뒤에 메모를 붙인다.
  - 예: `(온이 메모: 이 일기의 '최고의 팀플'은(는) 진심이 아니라 비꼬는 말이야. 진짜 마음은 '혼자 PPT' 때문에 속상한 거야.)`
- 같은 메모를 한 줄 요약에도 붙인다.
  - 요약이 반어를 곧이곧대로 적으면 회고가 틀어진다.
  - 예: x01 "기사님께 감사함"
  - 이 수정은 아직 다시 평가하지 않았다.
- **사전 필터**: 좋은 말 사전에 걸린 일기만 읽기 호출을 한다. 62편 중 25편이었다.
- **단어 규칙만 쓰는 방식은 버렸다.**
  - 조정에 쓴 50편에서는 다 맞혔다.
  - 따로 떼어 둔 12편에서는 3/12만 맞혔다.

### 다른 과제
- **감정 JSON**: 감정 이름을 enum으로 둔 JSON 스키마로 강제한다. 목록에 없는 감정은 바꿔 준다(`synonyms` 29개).
- **말로 쓰기 정리**: 숫자는 아라비아 숫자로 바꾼다(사 점 이 키로 → 4.2kg, 이호선 → 2호선).
- **새 과제**: 제목, 한 줄 요약, 회고, 개인화 질문, 대화로 쓰기(`chat.ask`·`chat.compose`)

## 후처리 필터 (`shared/ai/llm/filters.json`)
- 규칙 명세와 테스트 케이스 61개가 들어 있다.
- 구현은 두 가지이고, 둘 다 61개를 모두 통과한다.
  - Python: `filters.py`
  - Kotlin: `OutputFilter`

| 검사 | 방법 |
|---|---|
| 존댓말 | 따옴표 안은 빼고 본다 |
| 다른 문자 섞임 | 한자·가나·키릴 금지. 라틴 문자는 원문에 있거나 단위일 때만 허용 |
| 문장 수·질문 수 | 질문은 마지막 문장에 1개까지 |
| 진단·훈계 표현 | 금지 표현 목록과 대조 |
| 이름·숫자 | 원문에 있어야 한다. 한자어 수사는 숫자로 바꿔 비교(팔십 → 80, 사 점 이 → 4.2/4). 이름은 "OO이랑/이가", "OO님/쌤" 형태로 찾는다 |

**이름·숫자 검사 완화 (통합 후, `entities_eval.py`)**
- 앱처럼 tags.json 사람 사전을 넣고 돌리면, 저장된 E2B·E4B 출력 486개(답장·요약·정리) 중 39개(8.0%)를 버렸다. 모두 오탐이었다.
  - 낱말 안의 글자: '받아들여도'→아들, '깜짝'→짝, '이모지'→이모
  - 사전에 잘못 들어간 보통말: '같이', '사람', '좋아하는'
  - 호칭 차이: 원장쌤→원장님, 담임쌤→담임 선생님, 남친→남자친구
  - 보통명사: 가족들이랑, 친구
- 고친 뒤 0개(0%). 사람 사전 낱말은 어절 첫머리 + 조사일 때만 보고, 같은 태그의 다른 표현·호칭을 뗀 어간도 인정한다. 친구·가족 같은 보통명사 태그는 보지 않는다.
- 진짜로 잡아야 할 것: 같은 출력의 실제 이름·숫자를 지어낸 것으로 바꾼 114개 중 111개를 잡는다(전에도 111개였지만, 그중 4개는 '같이' 같은 오탐 덕에 우연히 잡혔다). 놓치는 3개는 '수빈이 워홀'처럼 이름 뒤에 조사가 없는 꼴이다. '기운이 '와 구별할 수 없어 보지 않는다.
- 한자어 수사는 앞뒤가 떨어져 있거나 단위가 붙을 때만 숫자로 읽는다. 전에는 '오늘'의 '오'를 5로 읽어서 '3년→5년'을 놓쳤다.

이 평가에서 고친 필터 오탐:
- "발전이네": 서술격 조사 '이네'를 이름으로 잘못 봤다.
- "그런가 봐": '~해 봐' 같은 훈계 표현으로 잘못 봤다.
- "육십 점이": 점수의 '점'을 소수점으로 잘못 읽었다.

## 한계
- **채점**
  - 채점자는 1명이고, 모델 이름을 알고 채점했다.
  - seed는 1개만 썼다.
- **반어 세트가 완전히 깨끗한 확인셋이 아니다.**
  - 반어 규칙과 감지 프롬프트는 x·d 세트를 보며 조정했다.
  - h 세트는 조정 전에 썼다.
  - 하지만 감지 프롬프트를 두 번째로 고칠 때는 h 결과를 보고 고쳤다.
- **실기기 확인 필요**
  - 반어 감지 호출과 감정 JSON 호출이 늘었다. 저장 한 번에 LLM을 최대 3번 부른다. 폰에서 약 2~4초가 더 걸릴 것으로 추정한다.
  - LiteRT-LM `ResponseFormat.json`이 Gemma 4에서 동작하는지 아직 확인하지 않았다.
