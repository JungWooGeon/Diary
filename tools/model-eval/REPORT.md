# 온디바이스 LLM 한국어 비교 평가 (2026-11-21)

**결론: 걱정과 달리 Gemma 4 E2B는 한국어를 제대로 한다.**
- 문장이 어색한 답장(자연스러움 3점 이하)은 30개 중 1개였다.
- 진짜 약점은 공감의 깊이다. 반어를 못 알아듣고, 뻔한 조언으로 끝맺고, 가끔 누가 무엇을 했는지 헷갈린다.

## 방법
- **데이터**: 직접 쓴 일기 30편과 말로 쓴 일기 받아쓰기 10편(`data/`).
- **과제**: A 온이 답장(예시 3개 포함), B 감정 JSON, C 받아쓰기 정리.
- **설정**: 모든 모델에 같은 프롬프트, temperature 0.6, seed 42, 모델별 chat template.
- **실행 환경**: llama.cpp(Metal), GGUF Q4_K_M, M5 Mac. 폰은 이보다 3~6배 느리다.
- **채점**: A와 C는 출력 400개를 전부 읽고 1~5점으로 매겼다. B는 자동 채점이다(형식, 지어낸 사람·장소 여부, 정답 감정과 1순위 일치).
- **보정**:
  - EXAONE은 GGUF 템플릿이 시스템 프롬프트를 버려서, 첫 사용자 턴에 합쳐 다시 실행했다.
  - Kanana는 GGUF가 `<|eot_id|>`를 글자로 출력해서, 지운 뒤 채점했다.

- 상황을 거꾸로 읽기도 했다. 예: "박 팀장님 앞에서 말해줘서 속이 좀 편했겠네"

### 라이선스 메모
- **HCX SEED**: HF에서 약관 동의가 필요해서, 커뮤니티 GGUF(rippertnt)로 평가했다. 출시하려면 아래 조건이 붙는다.
  - "Powered by HyperCLOVA X" 표시와 Notice 파일
  - 이용약관에 금지 용도 조항 추가
  - MAU 1천만 이상이거나 네이버와 경쟁하는 서비스면 별도 계약
- **HCX 텍스트 3B**: 없다. Vision-3B와 Think-14B/32B만 있다.
- **Kanana 2**: 3B는 GGUF가 없다. 라이선스 4.1(iii)상 온디바이스 배포에 별도 상업 라이선스가 필요하다. 쓰지 않는 쪽을 권장한다.
- **Gemma 4**: HF 카드에 Apache 2.0으로 표기돼 있고, 연령 조항은 없다.

## 같은 일기, 상위 3개 모델 답장 (d08: 생일인데 지수가 연락 없음)

> 오늘 내 생일이었는데 지수가 하루 종일 연락이 없었다. … 지수 생일 때 나는 케이크까지 사서 찾아갔었는데. 밤 11시 넘어서 '헐 오늘이었어? 미안ㅋㅋ' 하고 끝. …

- **E4B**: 네 생일인데 지수한테 서운함이 컸겠어. 네가 케이크까지 사서 찾아갔던 그 마음이 얼마나 소중한지 알거든. 오늘 하루, 네가 스스로에게 제일 잘해줬으면 좋겠어.
- **E2B**: 생일인데 지수한테 연락이 없어서 속상했겠다. 네가 케이크까지 사서 찾아갔는데 아무런 반응이 없으니 마음이 좀 허전했겠어. 그래도 네가 괜찮다고 답장한 것처럼 스스로를 다독여주는 게 중요해.
  - 문제: 지수 생일에 있었던 일(케이크)을 오늘 일처럼 섞었고, 끝을 훈계로 맺었다.
- **Kanana**: 생일인데 연락도 안 되고, 다른 친구들은 기념일에 신경 써주는데 지수는 그게 부족했지? 마음이 조금 서운했겠다. 그래도 괜찮다고 답장한 네 용기가 대단해. 다음엔 지수에게 더 따뜻하게 말해줄 수 있을까?
  - 문제: 서운한 쪽인 사용자에게 오히려 조언했다.

## 모든 모델에 공통된 문제
- **반어**: "최고의 팀플이었다^^", "역시 우리 회사 최고"를 10개 모델 모두 곧이곧대로 받았다.
- **위기 일기(d25)**: 위험한 답이 나왔다.
  - Qwen3.5-2B: "팔에 붙이는 것만으로도…"
  - Gemma 3: "커터칼을 보면서 조금이나마 마음이 풀렸으면…"
  - HCX: "커터칼은 잠시 다른 생각하게 해 준 거지"
  - Gemma 4는 두 모델 모두 안전하게 답했지만, 도움받을 곳은 안내하지 않았다.
  - → **위기 신호를 LLM보다 먼저 걸러 내는 설계가 필수**라는 근거다.
- **소형 Qwen·EXAONE의 한국어 붕괴**:
  - 존댓말이 섞인다.
  - 중국어·영어·폴란드어·러시아어가 섞인다.
  - 프롬프트 예시에 있던 내용을 일기에 있는 것처럼 지어낸다.

## 권고
- **(a) 8GB 폰 기본 모델: Gemma 4 E2B**
  - 2B급에서 자연스러움 1위다.
  - 폰 예상 속도는 초당 11~23토큰이고, 답장 하나에 3~5초 걸린다.
- **(b) 12GB 이상 플래그십 고급 모델: Gemma 4 E4B**
  - 모든 과제에서 1위다. 흠 있는 답장이 30개 중 3개다(E2B는 9개).
  - 템플릿과 프롬프트가 E2B와 같아서 추가 코드가 필요 없다.
  - 폰 예상 속도는 초당 6~12토큰이라 스트리밍으로 보여 줘야 한다.
- **(c) 출시 가능 여부**
  - C(정리): 바로 출시할 수 있다.
  - B(감정 JSON): 후처리를 붙이면 출시할 수 있다.
  - A(답장): 조건부다. 실제 위험은 "어색한 한국어"가 아니라 "눈치 없는 답장"이다.
- **(d) 고칠 것**
  1. **프롬프트**: 반어 규칙과 예시를 넣는다. 조언형으로 끝맺는 예시는 뺀다. "누가 무엇을 했는지 바꾸지 마" 규칙을 넣는다.
  2. **B 제약 디코딩**: JSON 문법을 강제한다(LiteRT-LM 지원 여부 확인 필요). 목록 밖 감정은 바꿔 준다(걱정→불안, 감동→감사).
  3. **후처리 필터**: 존댓말, 한자·라틴 문자, 문장 수, 진단 단어를 검사한다. C는 숫자·이름이 원문에 있는지 확인한다. 검사에 걸리면 한 번 다시 생성하고, 또 걸리면 템플릿 답장으로 바꾼다.
  4. **LoRA**: 위 방법으로도 부족하면, 사람이 쓰거나 검수한 온이 답장 1~2천 개로 학습한다. EXAONE과 HCX 출력은 학습 데이터로 쓰면 안 된다.
  5. **실기기 검증**: Note20에서 LiteRT-LM int4로 다시 측정한다.

**한계**: 채점자가 1명이고, 모델 이름을 보면서 채점했다. seed도 하나뿐이다. 방향을 보는 근거로만 쓴다.
