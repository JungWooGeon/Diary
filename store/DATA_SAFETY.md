# 데이터 보안 양식 답안 — 온이 일기 v2.0

> 근거: v2 브랜치 코드(2026-11-22, `3be1b45` 기준), Google Mobile Ads SDK 데이터 공개 안내, ML Kit 데이터 공개 안내.
> Play 기준
> - 기기 안에서만 처리되는 데이터는 '수집'이 아니에요.
> - 기기 밖으로 나가는 데이터는 SDK가 보내는 것까지 '수집'이에요.
> - 서비스 제공자가 앱 대신 처리하는 것, 사용자가 직접 요청한 전송은 '공유'가 아니에요.
> 개인정보처리방침(`web/public/legal/privacy.html`, 사본 `store/privacy_policy.md`)과 내용이 같아야 해요.

**앱이 기기 밖과 통신하는 곳** (코드에서 확인)

| 통신 | 코드 | 보내는 것 |
|---|---|---|
| Google 드라이브 백업 | `core/sync` `DriveApi` → `https://www.googleapis.com/drive/v3`<br>범위 `drive.appdata`만 사용 | 일기(본문·제목·감정·강도·태그·날씨·휴지통 표시), 사진(끌 수 있음), 온이의 한마디, 설정 일부, `entitlement.json`. 사용자 본인 계정의 앱 전용 폴더로 가요. 임베딩은 안 올려요. |
| Google 로그인 | `core/sync` `DriveAuth` (Credential Manager + Authorization API) | 계정 선택과 `drive.appdata` 동의. 이메일은 기기에만 둬요. |
| 날씨 (선택) | `core/data` `WeatherRepository` → `api.open-meteo.com`, `archive-api.open-meteo.com` | 위도·경도를 소수 첫째 자리(약 10km)로 줄인 값과 날짜. 사용자가 날씨를 누를 때만 보내요. |

| ML Kit 손글씨 모델 받기 (선택) | `core/vision` `MlKitHandwriting` → ML Kit 모델 서버 | 한국어 모델 파일(약 25MB) 요청만. 사용자가 '손글씨로 쓰기'를 켜고 '받기'를 누를 때만이에요. 나머지 ML Kit 모델은 Google Play 서비스가 받아요(앱 통신 아님). |

**v2에는 없는 것**
- Firebase(Crashlytics·Analytics·Remote Config)는 v2 빌드에 없어요. `_v1`에만 있어요. (ARCHITECTURE.md §1에는 아직 Firebase가 적혀 있어요.)
- 온디바이스 LLM(Gemma)과 모델 다운로드는 2026-11-22에 뺐어요. 앱의 답장은 준비된 문장("온이의 한마디")이에요.

## 1. 데이터 수집 및 보안 (첫 화면)

| 질문 | 답 |
|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** (AdMob, ML Kit, 날씨, 결제, 드라이브 백업) |
| 수집된 모든 사용자 데이터가 전송 중에 암호화되나요? | **예**: 위 통신이 모두 HTTPS예요. ML Kit도 HTTPS로 보낸다고 공식 문서에 적혀 있어요. |
| 사용자가 데이터 삭제를 요청할 수 있는 방법을 제공하나요? | **예**: 아래 '삭제 방법'. 삭제 URL은 `https://jungwoogeon.github.io/Diary/legal/privacy.html#delete` |
| 계정 생성 | **앱에서 계정을 만들 수 없음**<br>Google 로그인은 사용자 본인 드라이브에 접근하는 데만 써요. |
| 독립적인 보안 검토 | 아니요 |

**삭제 방법** (방침 제8조와 같아요)
1. 앱 → 마이 → 계정·데이터 삭제 (`MyViewModel.deleteEverything`)
   - 드라이브 appDataFolder 파일 전부 삭제 → 드라이브 권한 회수·로그아웃 → 기기의 앱 데이터 전부 삭제(`AppDataWiper`).
   - 드라이브 삭제가 실패하면 아무것도 지우지 않고 다시 시도하게 해요.
2. 앱 → 마이 → 휴지통에서 영구 삭제·비우기 (30일 지나면 자동으로 내용이 비워져요)
3. 앱을 삭제하거나 앱 데이터를 지우면 기기의 일기가 지워져요.
4. 드라이브 백업 삭제: Google 드라이브 웹 → 설정 → 앱 관리 → 온이 일기 → 숨겨진 앱 데이터 삭제
5. 이메일 문의 (운영자는 일기를 갖고 있지 않아 안내만 해요)

**위치 답을 고른 기준**
- 날씨만 놓고 보면 '선택 · 앱 기능'이에요.
- 그런데 Play는 데이터 유형마다 답을 하나만 받아요. AdMob이 IP로 늘 수집하므로 합친 답은 '필수'가 돼요.
- 날씨 결과는 기기에 캐시해요(`weather_cache`). 좌표 자체는 저장하지 않아요.

**AdMob 항목의 근거**
- [Google Mobile Ads SDK 데이터 공개 안내](https://developers.google.com/admob/android/privacy/play-data-disclosure): IP 주소(→ 대략적 위치), 사용자 제품 상호작용(→ 앱 상호작용), 진단 정보, 기기·계정 식별자.
- Google 광고 네트워크에서 쓰이므로 보수적으로 '공유 예'로 두었어요.
- ⚠️ 제출 직전에 위 페이지를 한 번 더 확인하세요. SDK 버전(25.5.0)에 따라 표가 바뀌기도 해요.

**ML Kit 항목의 근거** (2026-11-22 확인)
- [ML Kit Android 데이터 공개 안내](https://developers.google.com/ml-kit/android-data-disclosure) (최종 수정 2025-05-14)
  - 모든 기능 공통 수집: 기기 정보(제조사, 모델, OS 버전·빌드, ML 가속기), 앱 정보(패키지 이름, 앱 버전), 성능 지표(지연 시간 등), API 설정(이미지 형식·해상도 등), 기능 입출력 크기, 기능 버전, 이벤트 유형, 오류 코드, 설치 단위 식별자("사용자나 기기를 고유하게 식별하려는 것이 아님"). 목적: 진단·사용 분석.
  - Digital Ink: 설정한 언어도 수집.
  - 전송 중 HTTPS 암호화, "제3자에게 전송하지 않음".
  - 데이터 유형 매핑은 개발자가 정하라고 해요. 위 표처럼 '진단'과 '기기 또는 기타 ID'에 넣었어요.
- [ML Kit 약관](https://developers.google.com/ml-kit/terms) (최종 수정 2025-05-14)
  - "ML Kit APIs also send metrics about the performance and utilization of the APIs in your app to Google."
  - 온디바이스 API는 입력(이미지·영상·텍스트)과 결과를 Google 서버로 보내지 않아요. (잉크는 문장에 명시돼 있지 않지만 Digital Ink도 온디바이스 인식이에요.)
  - "앱 사용자에게 Google의 ML Kit 지표 처리를 알릴 책임"이 개발자에게 있어요 → 방침 제2조 4, 제6조, 제7조에 적었어요.
- 진단·기기 ID는 이미 AdMob 때문에 '예'라서 표의 답은 바뀌지 않고, 출처에 ML Kit을 더했어요.

## 3. ⚠️ 판단이 필요한 곳: 드라이브 백업

일기와 사진은 **사용자 본인 Google 드라이브의 앱 전용 폴더(appDataFolder)**로만 가요. 운영자 서버나 운영자 계정은 거치지 않아요.

| 선택지 | 내용 | 위험 |
|---|---|---|
| **A. 신고함 (권장, 위 표)** | Play 정의는 "기기 밖으로 전송 = 수집"이에요. 본인 드라이브를 예외로 두는 문구는 없어요. | 스토어에 "사용자 생성 콘텐츠·사진 수집"이 보여요. 대신 설명에 '내 드라이브에만'을 쓸 수 있어요. |
| B. 신고 안 함 | "운영자가 접근할 수 없는 사용자 본인 저장소"라는 해석이에요. | 심사에서 불일치로 지적될 수 있어요. 드라이브 API를 쓴다는 것이 코드에서 보여요. |

- A로 둘 때는 '선택'과 '앱 기능'만 체크하세요.
- 감정 기록을 **건강 정보**로 볼지도 정해야 해요.
  - Play의 건강 정보는 의료 기록, 증상 같은 것을 뜻해요. 감정 일기는 보통 '기타 사용자 생성 콘텐츠'로 신고해요.
  - 보수적으로 가려면 '건강 및 피트니스 › 건강 정보'에도 같은 답(선택, 앱 기능)을 체크하세요.
- 이메일 주소: Google 로그인으로 받은 계정 이메일은 기기에만 저장해요. 운영자에게 보내지 않으므로 '수집 안 함'이에요.

## 4. '수집 안 함'으로 두는 항목과 근거

| 항목 | 판정 | 근거 |
|---|---|---|
| 일기 본문의 AI 처리 | 수집 안 함 | 감정 분류·문장 임베딩(LiteRT, `core/ai`), 위기 감지(단어 규칙), 태그, 리포트 분석, 답장(준비된 문장)이 모두 기기 안에서 돌아요. 서버 AI API도, 내려받는 언어 모델도 없어요. |
| 문장 임베딩 | 수집 안 함 | `filesDir/ai/embeddings.bin`에만 있어요. 드라이브·자동 백업 대상이 아니고, 없으면 다시 계산해요. |
| 오디오 (말로 쓰기) | 수집 안 함 ⚠️ | 기본은 `createOnDeviceSpeechRecognizer`(API 31+)예요. 지원하지 않는 기기에서는 시스템 음성 인식기를 써요. 시스템 인식기(예: Google)는 음성을 자기 서버로 보낼 수 있지만 OS 서비스가 처리하는 것이고, 앱이 받는 것은 텍스트뿐이에요. 방침에 적어 두었어요. |
| 사진 선택 | — | Photo Picker를 써서 `READ_MEDIA_*` 권한이 없어요. 드라이브 백업 몫은 위 표에 넣었어요. |
| 사진 자동 태그 | 수집 안 함 (지표는 위 '진단') | ML Kit Image Labeling(Play 서비스)이 기기 안에서 라벨을 뽑아요. 사진과 라벨을 보내지 않아요. |
| 종이 일기 옮기기 | 수집 안 함 (지표는 위 '진단') | ML Kit Document Scanner + 한국어 Text Recognition v2(Play 서비스)가 기기 안에서 읽어요. 카메라 권한도 필요 없어요(스캐너 UI가 Play 서비스 쪽이에요). |
| 사진 스티커 | 수집 안 함 (지표는 위 '진단') | ML Kit Subject Segmentation(Play 서비스)이 기기 안에서 배경을 지워요. |
| 손글씨로 쓰기 | 수집 안 함 (지표는 위 '진단') | ML Kit Digital Ink가 내려받은 한국어 모델로 기기 안에서 인식해요. 획 데이터를 보내지 않아요. |
| 공유 카드 | 수집 안 함 | 사용자가 시스템 공유 시트로 직접 보내요(사용자 요청 전송). 카드에 일기 본문은 없어요(빛·감정 요약·준비된 문장). |
| 내보내기 zip | 수집 안 함 | 사용자가 고른 위치에 저장돼요. |
| 답장 신고 | 수집 안 함 | 사유는 기기에만 남아요 (`ReplyReports`). 일기의 `reported` 표시만 드라이브에 동기화돼요. |
| 잠금 PIN | 수집 안 함 | 기기에만 저장해요. 백업 규칙에서도 빠져 있어요. |
| 위젯 / 알림 | 수집 안 함 | 리마인더·주간 온이 편지·마음 예보 모두 로컬 알림이에요. FCM은 없어요. |
| Android 자동 백업 | 수집 안 함 | `allowBackup=true`로 일기 DB와 설정(기기 이전 시 사진도)이 사용자 본인 Google 백업에 들어갈 수 있어요. PIN·sync_meta·임베딩은 제외. Play 기준으로는 '수집'이 아니에요. 방침에는 적었어요. |
| 연락처, 메시지, 캘린더, 웹 기록, 파일, 정확한 위치 | 수집 안 함 | 해당 기능이 없어요. 위치 권한은 `ACCESS_COARSE_LOCATION`만 써요. |

## 5. 같이 답하는 항목 (앱 콘텐츠)

- **광고 ID**: 예, 사용함 → 광고, 분석, 사기 방지. (`play-services-ads`가 `AD_ID` 권한을 자동으로 병합해요.)
- **광고 포함**: 예.
- **UMP 동의**: EEA·영국 등 필요한 지역에서만 동의 화면을 띄워요 (`AdManager.gatherConsent`). 마이 → '광고 개인정보 옵션'(`privacyOptionsRequired`일 때만 보임)에서 바꿀 수 있어요.
- **방침 링크**: 온보딩 동의 화면과 마이 화면의 '이용약관'·'개인정보 처리방침' 줄이 웹 게시본을 열어요.

## 6. 남은 확인 (데이터·정책 관련)

1. *(정책)* 답장 신고는 기기에만 남아요. 앱 답장은 준비된 문장이라 Play AI 생성 콘텐츠 정책 대상은 아니에요. 웹의 Chrome 내장 AI 답장은 웹 전용이라 Play 심사 대상 밖이에요.
2. 사진 자동 태그(`VisionTools.photoTagSuggestions`)는 'AI 기능' 스위치와 무관하게 사진을 붙이면 라벨링을 돌리는 것으로 보여요. 끄면 ML Kit 지표도 안 나가게 하려면 스위치에 묶는 것이 맞아요(코드 QA 쪽 확인).
