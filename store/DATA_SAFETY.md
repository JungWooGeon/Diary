# 데이터 보안 양식 답안 — 온이 일기 v2.0 (versionCode 200)

> 근거: v2 브랜치 코드(2026-11-21, `0d5bcd4` 이후 작업 트리)와 Google Mobile Ads SDK 데이터 공개 안내.
> Play 기준
> - 기기 안에서만 처리되는 데이터는 '수집'이 아니에요.
> - 기기 밖으로 나가는 데이터는 SDK가 보내는 것까지 '수집'이에요.
> - 서비스 제공자가 앱 대신 처리하는 것, 사용자가 직접 요청한 전송은 '공유'가 아니에요.

**앱이 기기 밖과 통신하는 곳은 모두 5곳이에요** (코드에서 확인).

| 통신 | 코드 | 보내는 것 |
|---|---|---|
| Google 드라이브 백업 | `core/sync` `DriveApi` → `https://www.googleapis.com/drive/v3`<br>범위 `drive.appdata`만 사용 | 일기(본문·제목·감정·강도·태그·날씨), 사진, 온이 답장. 사용자 본인 계정의 앱 전용 폴더로 가요. |
| 날씨 (선택) | `core/data` `WeatherRepository` → `https://api.open-meteo.com`, `archive-api.open-meteo.com` | 위도·경도를 소수 첫째 자리(약 10km)로 줄인 값과 날짜. 사용자가 날씨를 누를 때만 보내요. |
| AdMob + UMP | `core/billing-ads` `AdManager`, `AdSlots` | SDK가 직접 수집해요 (아래 표). |
| Play 결제 | `core/billing-ads` `Billing` | 상품 `premium` 구매 조회와 확정. Google Play가 처리해요. |
| 대화형 AI 모델 다운로드 (선택) | `core/ai`, `https://huggingface.co/litert-community/` | 파일 요청만 보내요. 사용자 데이터는 보내지 않아요. 상대 서버에는 IP가 보여요. |

**v2에는 없는 것**
- Firebase(Crashlytics·Analytics·Remote Config)는 v2 빌드에 없어요. `_v1`에만 있어요.
- 설계서 §1에는 Firebase가 적혀 있어요. 나중에 넣으면 이 문서와 개인정보처리방침을 같이 고쳐야 해요.

## 1. 데이터 수집 및 보안 (첫 화면)

| 질문 | 답 |
|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유하나요? | **예** (AdMob, 날씨, 결제, 드라이브 백업) |
| 수집된 모든 사용자 데이터가 전송 중에 암호화되나요? | **예**: 위 5곳이 모두 HTTPS예요. |
| 사용자가 데이터 삭제를 요청할 수 있는 방법을 제공하나요? | **예**: 아래 '삭제 방법'을 보세요. ⚠️ 앱 안의 버튼이 아직 동작하지 않아요. |
| 계정 생성 | **앱에서 계정을 만들 수 없음**<br>Google 로그인은 사용자 본인 드라이브에 접근하는 데만 써요. 우리 서비스 계정을 만들지 않으므로 계정 삭제 URL은 필요 없어요. |
| 독립적인 보안 검토 | 아니요 |

**삭제 방법** (양식과 개인정보처리방침에 같이 쓰기)
1. 앱 → 마이 → 계정·데이터 삭제
   - 기기 데이터와 드라이브 백업을 함께 지워요.
   - ⚠️ **아직 구현되지 않았어요.** `MyScreen.kt`에서 onClick이 `{}`예요. 출시 전에 구현해야 해요.
2. 앱을 삭제하거나 앱 데이터를 지우면 기기의 일기가 지워져요.
3. 드라이브 백업 삭제
   - Google 드라이브 웹 → 설정 → 앱 관리 → 온이 일기 → 숨겨진 앱 데이터 삭제
4. 이메일 문의

## 2. 데이터 유형별 답안

| 데이터 유형 | 수집 | 공유 | 일시적 처리 | 필수/선택 | 목적 | 출처 |
|---|---|---|---|---|---|---|
| 위치 › **대략적인 위치** | 예 | 예 | 아니요 | 필수 | 앱 기능, 광고 또는 마케팅, 분석, 사기 방지·보안·규정 준수 | ① 날씨: 약 10km 단위 좌표를 Open-Meteo로 보내요 (선택).<br>② AdMob: IP로 대략적 위치를 추정해요. |
| 기기 또는 기타 ID › **기기 또는 기타 ID** | 예 | 예 | 아니요 | 필수 | 광고 또는 마케팅, 분석, 사기 방지·보안·규정 준수 | AdMob: 광고 ID, 앱 세트 ID |
| 앱 활동 › **앱 상호작용** | 예 | 예 | 아니요 | 필수 | 광고 또는 마케팅, 분석, 사기 방지·보안·규정 준수 | AdMob: 광고 노출, 클릭 |
| 앱 정보 및 성능 › **비정상 종료 로그**, **진단** | 예 | 예 | 아니요 | 필수 | 분석, 사기 방지·보안·규정 준수 | AdMob SDK 진단 정보. 앱 자체 크래시 SDK는 없어요. |
| 금융 정보 › **구매 내역** | 예 | 아니요 | 아니요 | 선택 (구매할 때만) | 앱 기능 | Play 결제 `premium`. 구매 상태는 기기에만 캐시해요. |
| 앱 활동 › **기타 사용자 생성 콘텐츠** (일기·감정 기록·온이 답장) | 예 ⚠️ | 아니요 | 아니요 | 선택 (백업을 켤 때만) | 앱 기능 | 드라이브 백업 |
| 사진 및 동영상 › **사진** | 예 ⚠️ | 아니요 | 아니요 | 선택 | 앱 기능 | 일기에 붙인 사진의 드라이브 백업 |

**위치 답을 고른 기준**
- 날씨만 놓고 보면 '선택 · 앱 기능'이에요.
- 그런데 Play는 데이터 유형마다 답을 하나만 받아요. AdMob이 IP로 늘 수집하므로 합친 답은 '필수'가 돼요.
- 목적에는 날씨용 '앱 기능'도 함께 체크하세요.
- 날씨 결과는 기기에 캐시해요(`weather_cache`). 좌표 자체는 저장하지 않아요.

**AdMob 항목의 근거**
- Google의 [Google Mobile Ads SDK 데이터 공개 안내](https://developers.google.com/admob/android/privacy/play-data-disclosure)에 따르면 SDK는 다음을 수집해요.
  - IP 주소(→ 대략적 위치)
  - 사용자 제품 상호작용(→ 앱 상호작용)
  - 진단 정보
  - 기기·계정 식별자
- Google 광고 네트워크에서 쓰이므로 보수적으로 '공유 예'로 두었어요. 전작(나의 컬러는?)도 같은 답이에요.
- ⚠️ 제출 직전에 위 페이지를 한 번 더 확인하세요. SDK 버전(25.5.0)에 따라 표가 바뀌기도 해요.

## 3. ⚠️ 판단이 필요한 곳: 드라이브 백업

일기와 사진은 **사용자 본인 Google 드라이브의 앱 전용 폴더(appDataFolder)**로만 가요. 운영자 서버나 운영자 계정은 거치지 않아요.

| 선택지 | 내용 | 위험 |
|---|---|---|
| **A. 신고함 (권장, 위 표)** | Play 정의는 "기기 밖으로 전송 = 수집"이에요. 본인 드라이브를 예외로 두는 문구는 없어요. | 스토어에 "사용자 생성 콘텐츠·사진 수집"이 보여요. 대신 설명에 '내 드라이브에만'을 쓸 수 있어요. |
| B. 신고 안 함 | "운영자가 접근할 수 없는 사용자 본인 저장소"라는 해석이에요. | 심사에서 불일치로 지적될 수 있어요. 드라이브 API를 쓴다는 것이 코드에서 보여요. |

- A로 둘 때는 '선택'과 '앱 기능'만 체크하세요.
- 감정 기록을 **건강 정보**로 볼지도 정해야 해요.
  - Play의 건강 정보는 의료 기록, 증상 같은 것을 뜻해요. 감정 일기는 보통 '기타 사용자 생성 콘텐츠'로 신고해요.
  - 보수적으로 가려면 '건강 및 피트니스 › 건강 정보'에도 같은 답(선택, 앱 기능)을 체크하세요.
- 이메일 주소: Google 로그인으로 받은 계정 이메일은 기기에만 저장해요. 재인증할 때 같은 계정인지 비교하는 데 써요. 운영자에게 보내지 않으므로 '수집 안 함'이에요.

## 4. '수집 안 함'으로 두는 항목과 근거

| 항목 | 판정 | 근거 |
|---|---|---|
| 일기 본문의 AI 처리 | 수집 안 함 | 감정 분류(LiteRT), 위기 감지, 태그, 답장(Gemma 4 E2B, LiteRT-LM)이 모두 기기 안에서 돌아요. 서버 AI API가 없어요. |
| 오디오 (말로 쓰기) | 수집 안 함 ⚠️ | 기본은 `createOnDeviceSpeechRecognizer`(API 31+)예요. 지원하지 않는 기기에서는 시스템 음성 인식기를 써요. 시스템 인식기(예: Google)는 음성을 자기 서버로 보낼 수 있어요. 다만 그건 OS 서비스가 처리하는 것이고, 앱이 받는 것은 텍스트뿐이에요. 방침에 이 내용을 적어 두었어요. |
| 사진 선택 | — | Photo Picker를 써서 `READ_MEDIA_*` 권한이 없어요. 사진은 기기에 압축해 저장해요. 드라이브 백업 몫은 위 표에 넣었어요. |
| 답장 신고 | 수집 안 함 | 신고 내용은 기기에만 남아요 (`ReplyScreen.kt`). |
| 잠금 PIN | 수집 안 함 | 기기에만 저장해요. 백업 규칙에서도 빠져 있어요. |
| 위젯 / 알림 | 수집 안 함 | 로컬 알림이에요. FCM은 없어요. |
| Android 자동 백업 | 수집 안 함 | `allowBackup=true`로 일기 DB와 설정이 사용자 본인 Google 백업에 들어갈 수 있어요. Play 기준으로는 '수집'이 아니에요. 방침에는 적었어요. |
| 연락처, 메시지, 캘린더, 웹 기록, 파일, 정확한 위치 | 수집 안 함 | 해당 기능이 없어요. 위치 권한은 `ACCESS_COARSE_LOCATION`만 써요. |

## 5. 같이 답하는 항목 (앱 콘텐츠)

- **광고 ID**: 예, 사용함 → 광고, 분석, 사기 방지. (`play-services-ads`가 `AD_ID` 권한을 자동으로 병합해요.)
- **광고 포함**: 예.
- **UMP 동의**
  - EEA·영국 등 필요한 지역에서만 동의 화면을 띄워요 (`AdManager.gatherConsent`).
  - ⚠️ `showPrivacyOptions`가 아직 어떤 화면에도 연결되어 있지 않아요. 동의가 필요한 지역의 사용자가 나중에 선택을 바꿀 수 있도록 마이 화면에 '개인정보 옵션' 줄을 넣어야 해요. `privacyOptionsRequired`일 때만 보이면 돼요.

## 6. 출시 전에 코드에서 고칠 것 (데이터·정책 관련)

1. **계정·데이터 삭제 버튼 구현** (`feature/my/MyScreen.kt`). 기기 DB, 사진, 드라이브 appDataFolder, 모델 파일을 지우고 로그아웃하도록 만들어야 해요.
2. **개인정보 옵션(UMP) 진입점 추가** (위 5절).
3. **온보딩 약관·방침 링크**
   - `CheckRow`가 link 화살표를 그리지만, 눌러도 문서가 열리지 않아요.
   - 방침 URL(`privacy_policy.html`을 올린 주소)을 열도록 연결하고, 마이 화면에도 '개인정보 처리방침' 줄을 추가하세요.
4. *(정책)* **답장 신고가 기기에만 남아요.**
   - Play AI 생성 콘텐츠 정책은 앱을 떠나지 않고 신고할 수 있으면 돼요. 지금 구조로도 요건은 충족해요.
   - 다만 Google은 신고를 받아 필터를 개선하라고 권해요.
   - 원하면 신고 후 "개발자에게도 보내기(이메일, 선택)"를 추가하세요. 이때 일기 본문은 빼고 답장 문구만 보내야 해요.
